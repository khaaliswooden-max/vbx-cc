## 2. Architecture (read this before any changes)

Two layers, strict separation:

```
┌──────────────────────────────────────────────────────────┐
│  SYSTEM OF RECORD                                        │
│  output/VBX_Command_Center_v1.xlsx                       │
│  • 12 sheets                                             │
│  • All operational data                                  │
│  • All target/goal definitions                           │
│  • All formula-driven metric computations                │
│  • Updated daily via direct entry in Excel               │
└──────────────────────────────────────────────────────────┘
                           ↑
                           │ generated by
                           │
┌──────────────────────────────────────────────────────────┐
│  WORKBOOK BUILDER (Python)                               │
│  scripts/build_command_center.py                         │
│  • Uses openpyxl                                         │
│  • Generates the workbook from scratch                   │
│  • Includes seed data + formula definitions              │
│  • Re-runs are idempotent — safe to rebuild              │
└──────────────────────────────────────────────────────────┘
                           ↓
                           │ read by
                           │
┌──────────────────────────────────────────────────────────┐
│  PRESENTATION LAYER (HTML)                               │
│  dashboard/VBX_Command_Center_Dashboard.html             │
│  • Single self-contained HTML file                       │
│  • Parses workbook client-side via SheetJS               │
│  • Renders KPIs, sparklines, drill-downs, scenarios      │
│  • No server, no build step, no installation             │
└──────────────────────────────────────────────────────────┘
```

**The invariant:** The workbook is the truth. The HTML reads it. Never let the HTML hold state that isn't in the workbook. Never put business logic in the HTML that contradicts the workbook's formulas.

The workbook contains 12 sheets. Three categories:

|---|---|---|

| `Meetings` | 4 | A=Date, B=Partner, C=Attendees, D=Type, E=Outcome, F=NextStep, G=Owner |

| `Active_Projects` | 4 | A=ID, B=Name, C=Client, D=Type, E=Value, F=Start, G=End, H=Status, I=%, J=PM |

| `NDAs` | 4 | A=#, B=Entity, C=Contact, D=Date, E=File, F=Status, G=Classification |
| `Agreements` | 4 | A=#, B=Party, C=Contact, D=Date, E=Type, F=File, G=Status, H=Notes |

### Reference sheet (operator edits targets in BLUE cells only)
| Sheet | Purpose |
|---|---|
| `Targets` | Year-1 ARR target, expense budget, BD cadence targets, pipeline coverage target. Cell C5 = ARR Target. Cell C6 = Expense Budget. Cells C9–C14 = revenue + P/L derivations. |

### Computed sheets (formula-driven — DO NOT edit values)
| Sheet | Purpose |
|---|---|
| `Metrics_Period` | Trailing-window engine. Pulls from input sheets via SUMIFS/COUNTIFS keyed to `As_Of_Date`. |
| `Dashboard` | Native-Excel summary view. Mirrors the HTML dashboard layout. |

### Header row convention
All input sheets place their column headers on **row 4** (not row 1). Rows 1–3 are reserved for:
- Row 1: Brand title row (navy fill, white text)
- Row 2: Section banner (descriptive instructions)
- Row 3: Spacer
- Row 4: Column headers

The Python builder uses `style_header_row(ws, row=4, last_col=N)` and the HTML parser uses `headerRow: 4` (0-indexed = row index 4 internally because the header is on Excel row 4, which is index 3, but data starts at index 4). **The HTML's `readSheet` function uses 0-indexed row 4 as the data start row — this matches Excel row 5.** Don't reshape this convention; multiple downstream consumers depend on it.

### Date convention
All date cells use `mm/dd/yyyy` format. The HTML parser uses `cellDates: true` in SheetJS so dates arrive as JS `Date` objects. The Python builder writes `datetime.date` objects with `cell.number_format = 'mm/dd/yyyy'`.

**Screenings** has a special quirk: column E is the *normalized* date (used by metrics), column I is the *display string* preserved from the original tracker (which sometimes contained values like "Pre-4/1/26" or "Apr 2026"). Always use column E for math.

## 6. Build, test, and validation commands

### Build the workbook
```bash
python scripts/build_command_center.py
```
Output → `output/VBX_Command_Center_v1.xlsx`

### Validate the workbook (zero formula errors required)
The Python xlsx skill ships with a recalc validator. After any builder change:
```bash
python /path/to/xlsx-skill/scripts/recalc.py output/VBX_Command_Center_v1.xlsx 60
```
Expected output:
```json
{"status": "success", "total_errors": 0, "total_formulas": 252}
```
If `total_errors > 0` or `total_formulas` decreases unexpectedly, investigate before committing.

### Verify HTML parsing against the workbook
The HTML parser must produce metrics that match the workbook's formula results. After changes to either side, run a headless verification:
```bash
node scripts/verify_parse.js
```
(Create this script if it doesn't exist — pattern is in `CLAUDE.md` §9.)

### Open the dashboard locally
```bash
# macOS
open dashboard/VBX_Command_Center_Dashboard.html

# Linux
xdg-open dashboard/VBX_Command_Center_Dashboard.html
```

## 7. Common workflows

### Workflow A — Add a new BD cadence KPI (e.g., "RFPs Submitted")

This is the most common change. Touch these files in order:

1. **`scripts/build_command_center.py`**
   - Add a new input sheet (or column on an existing sheet) for the underlying data
   - Add a row to the `bd_targets` list on `Targets` sheet
   - Add a new row to the `bd_kpi_specs` list in `Metrics_Period`
   - Add the row to the Dashboard `BD CADENCE` section

2. **`dashboard/VBX_Command_Center_Dashboard.html`**
   - Add the data parser for the new input sheet (if new)
   - Add a row to the `specs` array in `renderBDCadence()`
   - Add a drill-down case in `openDrill()`
   - Add the table renderer (if a new drill-down type)

3. **Rebuild + validate:**
   ```bash
   python scripts/build_command_center.py
   python /path/to/recalc.py output/VBX_Command_Center_v1.xlsx 60
   ```

4. **Bump version** in `CHANGELOG.md` under `[Unreleased]`.

### Workflow B — Modify a target value

If the operator wants to change the ARR target from $500K to $750K:

- **Do not** edit `scripts/build_command_center.py` defaults unless the change is permanent. The builder is for generating a fresh workbook; for everyday target changes, the operator edits cell `Targets!C5` directly in Excel.
- If permanent, update the seed value in the builder AND update `CHANGELOG.md`.

### Workflow C — Add a new input sheet

1. Create the sheet in `build_command_center.py` following the existing pattern: title row, banner row, header row at row 4, format defaults at rows 5–N.
2. Add a parser block in `parseWorkbook()` in the HTML.
3. Add KPIs to `Metrics_Period` if applicable.
4. Add drill-down support in `openDrill()` if KPI cards link to it.

### Workflow D — Restyle / brand drift fix

If a generated artifact has drifted from brand standards:
- Compare against §4 brand standards above
- Fix in the builder/HTML
- Regenerate
- Never patch the output file directly — fix the source

### Workflow E — Backfill historical data

The operator may ask to back-fill data into input sheets (e.g., "add the last 6 months of meetings"). Pattern:

1. Confirm exactly which fields are available for the historical records
2. Add a "back-fill block" to `build_command_center.py` with a clearly labeled list of records
3. Sort by date when populating to preserve chronological order
4. Re-run build + validate
5. If the historical data contains partner names, NDA references, or revenue figures, **the back-fill block must not be committed** — populate it once, generate the workbook, and revert the script before commit (or use a gitignored `scripts/_seed_data_local.py` that the main script imports if present)

## 8. Code style and conventions

### Python (workbook builder)
- 4-space indent, snake_case for functions and variables
- Constants in `UPPER_CASE` at top of file
- One concern per function (`style_header_row`, `set_col_widths`, etc.)
- Comment section dividers as `# === SECTION === #`
- Use `openpyxl.styles.PatternFill`, `Font`, `Alignment`, `Border` consistently — do not introduce inline style objects

### JavaScript (HTML dashboard)
- 2-space indent, camelCase for functions and variables
- `STATE` object holds all session state; never use globals outside it
- Render functions are pure: `renderX(data) → DOM`
- All money/date formatting via the `fmt*()` helper family
- No external JS dependencies beyond SheetJS (CDN). No npm, no React, no build step

### CSS
- CSS variables under `:root` for all brand tokens
- BEM-adjacent class naming: `.kpi-card`, `.kpi-card.accent-gold`, `.cadence-table thead th`
- No external CSS frameworks. No Tailwind. No Bootstrap.

### Markdown
- ATX-style headings (`#`, `##`, `###`)
- Tables for any data of 3+ rows
- Code fences with language hints
- Hard-wrap at ~100 chars in long-form sections; flexible in tables

## 10. Don't list (frequent traps)

- **Don't add a new sheet without updating the HTML parser.** The dashboard will silently ignore it.
- **Don't use Pandas for the workbook.** Stick with openpyxl. Pandas roundtripping breaks formulas.
- **Don't use SheetJS write-back to "update" the workbook from the HTML.** The HTML is read-only against the workbook.
- **Don't add localStorage or sessionStorage to the HTML.** The user opens it fresh each time and re-uploads — this is intentional, not a missing feature.
- **Don't add a backend.** This is a deliberately single-file local-only tool. Avoid Flask/Express/anything that introduces a server.
- **Don't replace SheetJS with a different XLSX parser** without a strong reason — SheetJS handles edge cases (dates, formulas, named ranges) that homegrown parsers miss.
- **Don't introduce icon libraries (Font Awesome, Lucide, etc.).** Use Unicode glyphs (✓ ✗ ⚠ → ←) sparingly. Brand consistency outweighs decorative variety.
- **Don't reformat the workbook's brand colors as Tailwind classes.** Hex values are the source of truth.
- **Don't auto-generate test data via fakers/Mimesis.** If sample data is needed, use the template in `data/targets_template.xlsx`.
